# Requirements coverage

Maps every decided requirement (the QA brief, section 2) to the automated tests (`e2e/`) or the manual checks ([push checklist](push-checklist.md)) that verify it. Anything not fully covered says why.

Test files are in `e2e/`. Each test runs on two viewports: **desktop** (1280 x 860) and **phone** (390 x 844), unless noted.

Legend: **Covered**: automated and passing. **Partly**: automated, with a gap noted. **Manual**: needs a real device or a real account. **Gap**: not covered yet.

## Totals

Counts are from the second full run (see the handoff note for the exact numbers and the run date).

- Automated tests: 206 cases in 12 spec files, run on two viewports (103 tests, each run on both).
- Known-failing test kept on purpose: 1 (D-01).
- Manual checks: see [push checklist](push-checklist.md), with the owner's results still to be recorded.

## Testing choices that affect what is covered

- **Test users and data:** each test creates its own accounts and deletes them. Data is set up through the API, not through the seed script, because the seed script works only for the first two `ALLOWED_EMAILS` and replaces their data.
- **Stand-in AI:** replies are scripted. Quality of model answers is **not** tested (manual, owner's judgement with the real provider).
- **Simulated offline:** the browser's offline mode is used. Real network loss on a phone is manual.
- **Push:** a local HTTPS stub receives real encrypted, signed pushes; the tests decrypt them. Delivery through Apple, Google or Microsoft push services is manual.
