Files (all AI-owned except the three shared-edit points listed in section 7):

- `src/services/ai/`:
  - `access.ts`: the opt-in gate, daily cap and token counters.
  - `context.ts`: builds the context, sending only what the switches allow.
  - `tools.ts`: the tool registry with risk tiers, and undo.
  - `actions.ts`: runs tool batches, applies the batch tier rule, handles confirm, reject, undo and expiry.
  - `chat.ts`: the persistent chat and streaming.
  - `profile.ts`: profile items and proposals.
  - `features.ts`: capture parsing, breakdown, Today proposal, fresh-look help, wording, reflection prompt.
  - `run.ts`: the shared JSON call with the gate and normalized failures.
  - `status.ts`: the state the interface reads.
  - `lifecycle.ts`: the export and deletion handler (registered as `ai`).

- `src/server/env.ts` and `.env.example`: `AI_PROVIDER`, `AI_API_KEY`, `AI_MODEL`, `AI_DAILY_REQUEST_LIMIT`.
- `docs/contracts/ai.md`: the contract.

Foundation and Backend rules followed: every read and write goes through `forUser()` and the Backend service layer; the `satisfies InsertOf<…>` / `patchFor<…>` workaround from `src/services/db-types.ts` is used for writes (blocker B1 still stands); errors use the standard shape; no content is logged (the logger is called only with event names).

## 3. How to set the AI key (owner)

1. Create a Groq account at https://console.groq.com and create an API key. The provider choice is tentative (contract section 1): confirm the free plan and the data settings first, as set out there.
2. Locally, add to `.env.local`: `AI_PROVIDER=groq` and `AI_API_KEY=<key>`. Do not commit it.
3. On Vercel, add the same two names under Project → Settings → Environment Variables for Production and Preview.
4. The app refuses to start if a real provider is named without a key, and it refuses `AI_PROVIDER=standin` in production.

To try another provider: set `AI_PROVIDER=mistral` or `openrouter` with a key (openrouter also needs `AI_MODEL`). Mistral's official pages showed no $0 API tier, so it is unlikely to work without a payment method.

## 4. Constants and where to change them

All in `src/shared/ai.ts`. Key values: confirmation threshold 3 items; pending expiry 24 hours; default daily cap 30 requests per person per day (overridable with `AI_DAILY_REQUEST_LIMIT`); chat history window 8 messages; context limits; profile limits; breakdown 2 to 5 steps; Today proposal 3 to 5 items; wording 160 characters. The full table is in the contract section 12.

Prompts and voice rules: `src/server/ai/prompts.ts`.

## 5. Stand-in cases

Trigger phrases and outputs are in contract section 14. They run through the same tool layer, so tiers, the action log and undo are exercised. Summary:

- `add <title>`, `note <text>`, `complete <title>`, `break down <title>`, `plan my day`: low tier, applied.
- `delete <title>`, `bulk complete`, `plan all` (4 items): confirm tier, pending.
- `remember <text>`: a profile proposal, refused when `ai_profile` is off.
- `error`: provider unavailable. `rest`: rate limited ("AI is resting").

## 8. Decisions for the owner to review

1. **Provider:** Groq as the tentative default, not yet confirmed (contract section 1). Mistral was not workable at $0 on the official pages.
2. **Editing a note or journal entry is confirm tier.** The brief lists editing and deleting journal entries as confirm; notes were not listed, so I chose the conservative option.
3. **Profile switch semantics:** the person can always manage their own profile items; `ai_profile` gates the AI's use of the profile and its proposals (contract section 3).
4. **Confirming needs `ai_features` on;** reject and undo are always allowed.
5. **Repeating tasks cannot be completed from chat in v1.** Completing one needs its own control, because undo needs a completion record that the service layer cannot remove.
6. **Clear chat keeps the action log.** Deleting the thread does not delete what the AI did.
7. **Daily cap** counts AI requests per person per day in the person's time zone. The default is 30. Two simultaneous requests could overshoot by one.
8. **Tapping "break it down"** is treated as the person's own request. It applies at low tier and is undoable.
9. **Data retention:** Groq may keep inputs and outputs for up to 30 days unless the owner changes the Data Controls setting. Recommend the owner decides before real use.
10. **The first-run warning wording** is in contract section 13.4 for the Frontend AI agent to use.

## 9. Known limits

- Groq's published limit for this model family is 8,000 tokens per minute on the Developer tier, and the limits are shared by every user of the key. Context is kept small, but a long conversation can still hit the limit; the person then sees "AI is resting".
- The provider's streamed text can contain a forbidden word before the check runs. The prompt forbids it, but streaming cannot be filtered in full. Feature replies and wording are checked fully.
- The action log stores plain summaries that include task titles. They are the person's own data and are never written to server logs.
- Recurring tasks cannot be completed from chat (section 8, item 5).

## 10. Where the Frontend AI and Nudges agents start

- **Frontend AI:** `docs/contracts/ai.md`. Start with section 10 (endpoints) and section 11 (reason codes). The chat stream is NDJSON (section 4). Action cards carry `canUndo` and `status`. Use section 13.4 for the first-run warning. `GET /api/ai/status` drives the "AI is resting" states.
- **Nudges:** `docs/contracts/ai.md` section 9, "Wording". Call `generateNudgeWording(ctx, { taskId, reason })` from `src/services/ai/features.ts`. Use the returned `text` when `source` is `"ai"`; otherwise use your fixed template. The function honors `ai_features` and never reads notes. Check your own `nudges` switch and quiet hours before calling it.
